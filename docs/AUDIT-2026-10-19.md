# sub-maker audit — 2026-10-19

Product + codebase audit of `github.com/tsonubin/sub-maker` at commit `0f0ab27` (v0.2.1 line).
Scope: all of `src/` (6.9k lines Rust), templates, install/packaging scripts, CI, docs.
Method: full read of core modules, delegated sweeps of TUI / setup / packaging, `cargo test`
baseline (28 pass), line-level verification of every finding cited here.

---

## 1. What it is and for whom

**sub-maker** is a single-binary Rust TUI + CLI that turns a fresh Linux VPS into a
multi-protocol proxy server: it drives a ratatui wizard (identity → protocols → certs →
per-protocol credentials → review), downloads and configures **sing-box** (VLESS+Reality,
Hysteria2, TUIC v5, AnyTLS, SS2022), obtains TLS certificates (Certbot / acme.sh /
existing / self-signed), writes systemd units, generates share-link URIs, and runs a small
HTTP server (default `:8964`) that serves a Clash YAML subscription (`/sub`) and raw node
URIs (`/raw`) behind a token.

**Audience:** the operator of one or a few personal VPSes who wants modern proxy protocols
without hand-editing sing-box JSON — Chinese-market Clash ecosystem clients (Clash Meta,
Stash) are clearly the primary consumer (Chinese proxy-group names, ACL4SSR rule sets).
Secondary audience: friends/family sharing the subscription; the `link --passcode` flow
exists specifically to hand out the URL over SSH without exposing it to shell history.

**What it's good at:** the end-to-end happy path is genuinely one command. Protocol
coverage is current, share-URI generation is careful (URL-encoding, SS2022 SIP022
userinfo), the Clash output is thoughtfully rule-staged, tar extraction is hardened against
path traversal, passcode verification is constant-time, and there is a demo mode for
no-root smoke tests. Distribution is unusually complete for a personal tool (raw binaries,
deb/rpm, Homebrew tap, checksummed releases).

| Area | State |

runs `cargo test --locked` without a clippy/fmt gate.

## 4. Designs for top items

### 1. ACME email command injection (landed)

`setup/certs.rs:28-31` interpolates the wizard-supplied email into `sh -c
"curl https://get.acme.sh | sh -s email={email}"`. Any `;`/`$()`/backtick in the email runs
arbitrary commands **as root**.

Design: never interpolate. Invoke `sh -c '<fixed script>' _ "$email"` so the email arrives
as a positional parameter (`$1`) the shell cannot re-parse; tighten `curl` to `-fsSL`.
Additionally reject emails outside `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+` at the boundary
(TUI save + apply) as defense in depth. The `curl | sh` installer itself remains
unverified (see #5 family); pinning get.acme.sh to a known hash is a follow-up Shay call.

### 2. `/tmp` races during binary install (landed)

`download_sing_box`/`download_subconverter` use fixed paths `/tmp/sing-box.tar.gz` and
`/tmp/sing-box-extract`; `File::create` follows symlinks, so a local user can pre-plant a
symlink and have root overwrite arbitrary files, or plant a `sing-box` entry in the extract
dir that gets promoted to `/usr/local/bin/sing-box`.

Design: create one private work directory per run (`/tmp/sub-maker-<pid>-<rand>`, created
with `fs::create_dir` which fails if the name exists, then `chmod 0700`); all downloads,
extracts and staging happen inside it; files opened with `create_new(true)`; the directory
is removed on completion. Installation to the final path is a copy + `chmod 0755`, not a
cross-device `rename`. This also fixes the EXDEV bug (#9).

### 3. Token exposure / unit injection (landed)

`apply.rs:564-599` string-replaces the user-supplied `sub_token` into
`Environment=SUB_MAKER_TOKEN={{.Token}}` and `fs::write`s the unit with default mode 0644:
any local user can read the token (and with it every node credential), and a token
containing `\n` injects arbitrary unit directives; `%` triggers systemd specifier expansion.

Design: (a) validate `sub_token` at config build and at unit render — allow
`[A-Za-z0-9._~-]`, reject everything else with a clear error; (b) write the token-bearing
unit with mode 0600 (systemd reads it as root regardless); (c) keep rendering
escaping-hostile by construction — validated values only enter `render_simple`.

### 4. Certificate renewal gap (landed — shipped default below)

`ensure_certificates` copies ACME results once into `/etc/sub-maker/certs/{fullchain,privkey}.pem`
and sing-box is pointed at the copy. Certbot's timer/acme.sh's cron renew the *original*;
nothing re-copies or reloads sing-box. After ~90 days the served cert is expired. GUIDE.md
even claims "Generating and renewing real TLS certificates" (line 37) — it only obtains.

Design options (product decision):
- **A — deploy hooks (recommended):** install a certbot deploy-hook / acme.sh
  `--install-cert` copy+`systemctl reload sing-box`; sub-maker owns the copy lifecycle.
- **B — point at live paths:** set `cert_path` to `/etc/letsencrypt/live/<domain>/…`
  directly; no copies to go stale, but couples sing-box to certbot layout and permissions.
- **C — renewal timer:** a `sub-maker-renew.service/.timer` unit that re-runs
  `ensure_certificates` + reloads sing-box weekly; works for every strategy uniformly.

**Shipped default (2026-10-19):** a self-contained variant of C — `sub-maker renew`
re-copies the ACME client's renewed files into `/etc/sub-maker/certs/`, validates the
pair, and restarts sing-box **only when the managed cert content changed**; self-signed
certs are regenerated when they expire within 14 days; `existing` strategy is
validate-only. Issuance/renewal stays owned by certbot's timer / acme.sh's cron. A
`sub-maker-renew.timer` (weekly, `Persistent=true`) is written and enabled by setup.
This keeps the layout contract (`/etc/sub-maker/certs`) intact and needs no coupling to
certbot's directory scheme. If a deploy-hook approach is preferred later, the `renew`
command is idempotent and can simply be invoked from the hook.

### 5. install.sh supply chain (landed)

Checksum mismatch today prints a warning and installs anyway (`install.sh:134-151`); the
binary download goes to fixed `/tmp/sub-maker` (symlink-clobberable by locals).

Design: `mktemp` for the download target; on checksum **mismatch** abort unless
`SUB_MAKER_INSTALL_INSECURE=1`; missing checksums.txt → abort by default (allow override),
since `checksums.txt` is published with every release. Build-from-source fallback stays
explicit.

### 6. Silent-wrong-config wizard paths (landed, partial)

Four independent fallbacks produce a working-looking but wrong install:
blank server address → `127.0.0.1` in every share link; unparsable port input silently
keeps the old value; "no protocols selected + Enter" silently selects all five;
back-navigation into Certs wipes a typed Cloudflare token.

Design: validation errors instead of fallbacks — server address required (editor:
blank keeps current), port fields must parse to 1..=65535 with a visible inline error,
empty protocol selection is refused with "select at least one protocol", and
`prepare_cert_extra` preserves already-typed values when the strategy is unchanged.
Also landed: the DNS modal defaults to "Back to edit" (items 12/13 — field pages scroll
to keep the focused field visible on 80×24). Deferred: review-screen visibility of
generated secrets.

### 7. Escaping of generated configs (landed)

`assets::render_simple` does raw string substitution into JSON templates and the Clash
YAML is built with `format!`; a `"`/`\`/newline in any remark, SNI or password breaks the
output — and the JSON break is only *warned* about (`apply.rs:539-541`) before the broken
config is written and sing-box fails at service start.

Design: JSON-escape every substituted value at render time; YAML-escape (`"`/`\`)
interpolated strings in `nodes_to_clash_proxies_with_names`; **fail** `apply` when the
assembled sing-box config doesn't parse, instead of writing it. Regression tests at the
render boundary.

### 8. Subscription server hardening (landed)

`server.rs` accepts the well-known default token `changeme-in-config` when
`SUB_MAKER_TOKEN` is unset, compares tokens with `!=` (timing-unsafe), has no socket read
timeout (one idle connection wedges the single-threaded accept loop forever) and handles
connections sequentially (one slow client stalls every subscriber).

Design: refuse to serve in non-demo mode with a missing/default token; compare digests with
`subtle::ConstantTimeEq` (already a dependency); `set_read_timeout`/`set_write_timeout` on
accepted streams; handle each connection on a short-lived thread (`thread::spawn` — fine at
this scale; the state is already `Arc`). Token-in-query-string and cleartext `http://`
links are a protocol change → Shay (#14).

### 9. Update/install path bugs (landed)

`--update` deletes `/opt/subconverter` wholesale including the generated `pref.ini`;
unsupported architectures silently download amd64; `fs::rename` from `/tmp` fails EXDEV
when `/tmp` is tmpfs; `extract_tar_gz` chmods 0755 on **every** extracted file because the
extract dir path contains "sing-box".

Design: preserve `pref.ini` across subconverter replacement (restore after extract if it
existed); map `std::env::consts::ARCH` → asset with `_ => bail!(unsupported arch)`; install
via copy+chmod (fixes #2's rename too); drop the path-substring chmod — chmod only the
final binary at install time.

### 10. Deduplicate wizard/config editor (**Shay**)

`wizard.rs` and `tui/config.rs` duplicate Step/Field/flow/key-handling/draw code (~85%),
already diverged in 9 observable behaviors (footer hints, back-keys, cert prefill,
`apply_cert_extra` bounds check…). Design: one `tui/state.rs` owning `Step`, `Field`,
validation, save/load (keyed fields, not positional indices), and `tui/screen.rs` draw
helpers; `Wizard`/`Editor` become thin adapters with `blank_semantics: Generate | Keep`.
This is the single highest-leverage maintainability move but it is a ~2k-line refactor of
the least test-covered surface — worth its own PR with a manual TUI walkthrough checklist,
not a drive-by.

Progress (2026-10-19): the seam is being taken over piecewise — `edit_text`/`insert_text`,
the `Field` type, and the key→edit mapping (`Field::edit`/`Field::paste`) are now single-
owner modules in `src/tui/` shared by both screens; each screen keeps only its
step-aware `focused_field()` borrow. What remains duplicated is step flow, draw code, and
save/load semantics.

  symlinks; extraction into attacker-pre-creatable dir; `walkdir` `is_file()` follows
  symlinks before promoting to `/usr/local/bin`.
- **S3** `setup/downloader.rs:24-47,109-175` — no checksum/signature check on sing-box /
  subconverter binaries (from `asdlokj1qpi233/subconverter`, a third-party fork); "latest"

- **S4** `setup/apply.rs:580-593` + `templates/sub-maker-sub.service.tpl:9` — token

- `cargo test` baseline: 28/28 pass pre-change; post-change targeted runs green
  (`setup::` 14/14 incl. unit-permission/token-escape/pref.ini regressions,
  `server::` 4/4 incl. YAML-escape and token-compare, `setup::downloader` 3/3 incl.
